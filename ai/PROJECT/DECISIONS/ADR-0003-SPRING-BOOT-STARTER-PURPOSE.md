# ADR-0003: Spring Boot starter purpose

## Status

Accepted.

## Context

`contract-spring-boot-starter` originally shipped as a marker class plus a
transitive dependency on `contract-core`. That shape did not justify a starter
module: there was no auto-configuration metadata, no Spring-specific runtime
integration, and no documented behavior beyond dependency aggregation.

ADR-0002 already defines which Spring Boot release lines are supported. This
decision defines what the starter actually does inside those supported lines.

The contract model remains framework-agnostic and compile-time-first. Any
Spring Boot integration therefore needs to stay optional, non-invasive, and
clearly bounded so that `contract-core` remains the source of enforcement.

## Decision

`contract-spring-boot-starter` becomes a real Spring Boot integration module.

The starter now publishes Spring Boot auto-configuration metadata and provides:

- a public `@AutoConfiguration` entry point,
- `ContractSpringProperties` under the prefix `contract.spring`,
- an opt-in servlet `HandlerExceptionResolver` controlled by
  `contract.spring.web-exception-handler.enabled=false` by default,
- an actuator `InfoContributor` controlled by
  `contract.spring.actuator-info.enabled=true` by default when actuator is on
  the classpath.

The web exception resolver only handles contract-generated runtime violations.
It maps generated `IllegalArgumentException` precondition failures to HTTP `400`
and generated `IllegalStateException` postcondition failures to HTTP `500`.
Non-contract exceptions are ignored.

The starter does not add proxies, reflection-based contract evaluation, or any
new enforcement mechanism. Contract checks remain generated by
`contract-core`'s annotation processor.

## Consequences

The starter now has a concrete runtime purpose that justifies its artifact:

- Spring Boot applications can opt into minimal HTTP translation for contract
  violations without adding custom glue code.
- Actuator users get lightweight visibility that the contract starter is active
  when actuator is present.
- Non-web and non-actuator applications do not pay for those integrations
  unless the relevant classes are present and the feature is enabled.

This decision also makes the starter part of the public Spring-facing API
surface. Future compatibility work must document the auto-configuration class,
configuration properties, and generated-exception mapping as supported behavior.
